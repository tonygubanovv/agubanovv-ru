# Личный сайт

Новый статический сайт на Astro для `https://tonygubanovv.github.io/agubanovv-ru/`.
Основной инструмент — Codex, дополнительный — Qoder. Правила одинаковы для всех агентов. [Карта документации](docs/README.md), [руководство владельцу](docs/guides/START_HERE.md), [публикация](docs/guides/PUBLISH.md).
Старое приложение удалено из рабочего дерева. Git-история сохранена. Публикации и кейсы пока не добавлены: в разделах показаны законченные пустые состояния.

## Локальный просмотр

Нужны Node.js 24 LTS и npm. Первичная установка: `npm ci`.

- `npm run dev` — разработка, адрес `http://127.0.0.1:4321/agubanovv-ru/` (если порт занят, Astro напечатает другой).
- `npm run check` — строгая проверка Astro и TypeScript.
- `npm run build` — статические файлы в `dist/`.
- `npm run smoke` — проверка файлов сборки, canonical, base, локальных ссылок и якорей, изображений, языка и H1; выполняется после сборки.
- `npm run preview` — просмотр готовой сборки по локальному адресу из терминала.

При пустых коллекциях Astro сообщает `No files found` / `collection ... is empty`. Это ожидаемо до первой публикации; проверки не отключены.

## Что создано

Главная, блог, проекты, 404, шаблоны статей и кейсов, страницы тегов. Теги и отдельные материалы генерируются только при наличии опубликованных Markdown-файлов. Есть оглавление при четырёх и более подзаголовках, связанные материалы по общим тегам, адаптивные карточки, оптимизация обложек средствами Astro.

Общие компоненты отвечают за шапку, доступное мобильное меню, подвал, метаданные и карточки. Системная тема работает через CSS даже без JavaScript; ручной выбор темы сохраняется, когда браузер разрешает localStorage. Ранний скрипт применяет сохранённую тему до отрисовки. Меню без JS открывается нативным `details`.

У каждой индексируемой страницы свой title, description и canonical. Есть Open Graph/Twitter, общее изображение `public/og.png` (исходник `public/og.svg`), favicon, sitemap и robots. На главной — WebSite JSON-LD; у статей — BlogPosting. Автор добавляется в разметку только после подтверждения имени. Страница 404 закрыта от индексации и исключена из sitemap.

## Где менять данные

Все сведения о владельце, ссылки, навигация, вводные тексты и настройки аналитики — в `src/config/site.ts`. Сейчас подтверждены специализация из ТЗ и адрес GitHub; имя, биография, Telegram и email не подставлены. Передайте агенту нужные данные обычным текстом — писать код самостоятельно не требуется.

- `src/components/` — общие элементы.
- `src/layouts/` — оболочка сайта и шаблон материала.
- `src/styles/global.css` — палитра, размеры, адаптивность, доступность.
- `src/content.config.ts` — схемы публикаций.
- `src/content/blog/` и `src/content/projects/` — только готовые к публикации Markdown-файлы.
- `src/utils/urls.ts` — единая обработка локальных URL с base.

Имя файла материала — латиница, цифры и дефисы; оно задаёт постоянный slug. Черновики остаются вне репозитория. Схемы не принимают пустые обязательные поля, неправильные даты, более шести тегов или обложку без alt. Дату можно писать как `2026-10-22` или `"2026-10-22"`; вывод — по-русски, часовая зона Europe/Moscow. MDX не установлен, поскольку интерактивных публикаций нет.

Новая статья требует `title`, `description`, `date`, `category`; `tags`, `updated`, `featured`, `cover` необязательны. Кейс требует `title`, `summary`, `date`; `role`, `tags`, `featured`, `cover` необязательны. Обложка — объект `src` (относительный путь к изображению) и `alt`. Тело Markdown начинаетcя с H2: H1 создаёт шаблон. Для изображений с подписями доступны `figure` / `figcaption`. Внутренние ссылки и изображения из public в Markdown должны включать `/agubanovv-ru/`; финальный smoke-тест проверяет фактические ссылки и размеры изображений. Скриншоты и результаты публикуются только с разрешения владельца.

Страницы тегов используют устойчивое кодирование UTF-8 в URL: разные названия не сливаются из-за совпавшей транслитерации.

## Зависимости

Astro — статическая генерация и обработка изображений; официальный `@astrojs/sitemap` — карта сайта. Tailwind CSS 4 и `@tailwindcss/vite` — CSS через Vite. `@astrojs/check` и совместимый TypeScript 6 — диагностика. TypeScript 7 пока не поддерживается установленной версией Astro check. Версии зафиксированы в `package-lock.json`. React, Next.js, UI-фреймворки и внешние шрифты не используются.

Официальные инструкции: [Astro](https://docs.astro.build/en/getting-started/), [Tailwind для Astro](https://tailwindcss.com/docs/installation/framework-guides/astro).

## Аналитика

`src/components/Analytics.astro` по умолчанию не выводит скрипт и не делает запросов. Включение требует реального `yandexId`, отдельного согласования информирования посетителей и `privacyApproved: true`. Smoke-тест сейчас запрещает активную Метрику; при её согласованном подключении агент должен обновить проверку под утверждённый режим. Ни один ID не выдуман.

## GitHub

Публикация выполняется только после отдельного разрешения владельца на push. Workflow проверяет `npm ci`, `check`, `build`, `smoke`; передаёт только `dist` и разрешает deploy только из `main`. Деплой имеет отдельные минимальные права. Никакие токены и `.env` для запуска не нужны.

Однократные настройки владельца:

1. Settings → Pages → Build and deployment → Source: GitHub Actions.
2. Проверить Secret scanning, Push protection и Dependabot alerts, включить 2FA учётной записи.
3. При желании настроить обновления зависимостей через проверяемые pull request.

Custom domain пока не задавать. `CNAME` отсутствует. Последующая смена домена описана в `docs/guides/DOMAIN_LATER.md`.

Фактическая проверка опубликованного адреса и запуска Actions возможна после разрешённого push. Lighthouse-оценки не заявляются без измерения.
