# Личный сайт

Новый статический сайт на Astro для `https://agubanovv.ru/`.
Основной инструмент — Codex, дополнительный — Qoder. Правила одинаковы для всех агентов. [Карта документации](docs/README.md), [руководство владельцу](docs/guides/START_HERE.md), [публикация](docs/guides/PUBLISH.md).
Старое приложение удалено из рабочего дерева. Git-история сохранена. В блоге опубликована первая статья о llms.txt, перенесённая из Teletype по прямому запросу автора. Кейсы пока не добавлены: в проектах показано законченное пустое состояние.

## Локальный просмотр

Нужны Node.js 24 LTS и npm. Первичная установка: `npm ci`.

- `npm run dev` — разработка, адрес `http://127.0.0.1:4321/` (если порт занят, Astro напечатает другой).
- `npm run check` — строгая проверка Astro и TypeScript.
- `npm run build` — статические файлы в `dist/`.
- `npm run smoke` — проверка файлов сборки, canonical, base, локальных ссылок и якорей, изображений, языка и H1; выполняется после сборки.
- `npm run preview` — просмотр готовой сборки по локальному адресу из терминала.

При пустых коллекциях Astro сообщает `No files found` / `collection ... is empty`. Это ожидаемо до первой публикации; проверки не отключены.

## Что создано

Главная, блог, проекты, 404, шаблоны статей и кейсов, страницы тегов. Теги и отдельные материалы генерируются только при наличии опубликованных Markdown-файлов. Есть оглавление при четырёх и более подзаголовках, связанные материалы по общим тегам, адаптивные карточки. Картинки сайт не пережимает: отдаёт файлы ровно так, как их загрузил владелец.

Общие компоненты отвечают за шапку, доступное мобильное меню, подвал, метаданные и карточки. Системная тема работает через CSS даже без JavaScript; ручной выбор темы сохраняется, когда браузер разрешает localStorage. Ранний скрипт применяет сохранённую тему до отрисовки. Меню без JS открывается нативным `details`.

У каждой индексируемой страницы свой title, description и canonical. Есть Open Graph/Twitter, общее изображение `public/og.png` (HTML-исходник `scripts/templates/og.astro`), favicon, sitemap и robots. На главной — WebSite JSON-LD; у статей — BlogPosting. Автор добавляется в разметку только после подтверждения имени. Страница 404 закрыта от индексации и исключена из sitemap.

## Где менять данные

Все сведения о владельце, навигация, вводные тексты и настройки аналитики — в `src/config/site.ts`. Контакты задаются в одном объекте `links`: `telegram` (полный URL) и `email` (адрес). `contactLinks()` используется всеми блоками; изменение значения действует сразу во всех местах. Пока контакты не предоставлены, ссылки и контактный блок скрыты. Личный GitHub на сайте не показывается. Передайте агенту нужные данные обычным текстом — писать код самостоятельно не требуется.

В Markdown контакты тоже остаются глобальными: `[Написать в Telegram](contact:telegram)` и `[Написать письмо](contact:email)`. При рендеринге подставляется значение из того же конфига. Если ссылка ещё не настроена, сборка останавливается с понятной ошибкой; нерабочая ссылка не публикуется.

Личный Telegram владельца настроен в общем конфиге. Hover кнопок не смещает элементы, некликабельные карточки не реагируют на наведение. `robots.txt` указывает на `/sitemap.xml`: этот адрес содержит индекс, автоматически созданный официальной интеграцией sitemap. Open Graph и Twitter используют те же title и description, что SEO, и общую обложку либо обложку материала.

- `src/components/` — общие элементы.
- `src/layouts/` — оболочка сайта и шаблон материала.
- `src/styles/global.css` — палитра, размеры, адаптивность, доступность.
- `src/content.config.ts` — схемы публикаций.
- `src/content/blog/` — только готовые к публикации Markdown-файлы.
- `src/utils/urls.ts` — единая обработка локальных URL с base.

Имя файла материала — латиница, цифры и дефисы; оно задаёт постоянный slug. Черновики остаются вне репозитория. Схемы не принимают пустые обязательные поля, неправильные даты, более шести тегов или обложку без alt. Дату можно писать как `2026-10-22` или `"2026-10-22"`; вывод — по-русски, часовая зона Europe/Moscow. MDX не установлен, поскольку интерактивных публикаций нет.

Новая статья требует `title`, `description`, `date`, `category`; `tags`, `updated`, `featured`, `cover` необязательны. Кейс требует `title`, `summary`, `date`; `role`, `tags`, `featured`, `cover` необязательны. Обложка — объект `src` (относительный путь к изображению) и `alt`. Тело Markdown начинаетcя с H2: H1 создаёт шаблон. Подпись под картинкой собирается в `figure` / `figcaption` сама по курсивной строке под изображением, вручную теги писать не нужно. Внутренние ссылки и изображения из public в Markdown должны использовать `https://agubanovv.ru/`; финальный smoke-тест проверяет фактические ссылки и размеры изображений. Скриншоты и результаты публикуются только с разрешения владельца.

Для переноса без единой текстовой правки по отдельному указанию автора есть `preserveText: true`: исходный H1 и тело материала защищены от автоматического Typograf; интерфейс и SEO по-прежнему обрабатываются. Не включать этот режим по умолчанию. У статьи `llms-txt-useless.md` сохранены оригинальные абзацы, заголовки, выделения, ссылки и дата первой публикации 06.10.2026; иллюстрация взята из OG исходной публикации.

Блоки в тексте владелец пишет короткими метками, а не HTML: `:::цитата Имя, роль`, `:::цитата-акцент Имя, роль` (та же карточка на акцентной заливке) и `:::заметка`, каждая партия закрывается строкой `:::`. Подпись под картинкой — курсивная строка сразу под ней. Синтаксис и внешний вид описаны в `docs/guides/BLOG_BLOCKS.md`, `docs/specs/CONTENT_AND_SEO.md` и `docs/specs/DESIGN_SYSTEM.md`.

Страницы тегов используют устойчивое кодирование UTF-8 в URL: разные названия не сливаются из-за совпавшей транслитерации.

## Зависимости

Astro — статическая генерация и обработка изображений; официальный `@astrojs/sitemap` — карта сайта. Tailwind CSS 4 и `@tailwindcss/vite` — CSS через Vite. `@astrojs/check` и совместимый TypeScript 6 — диагностика. TypeScript 7 пока не поддерживается установленной версией Astro check. Версии зафиксированы в `package-lock.json`. React, Next.js и UI-фреймворки не используются.

Onest и JetBrains Mono поставляются локально через Fontsource (OFL-1.1). Typograf (MIT) оформляет русский и английский текст при рендеринге HTML; parse5 (MIT) безопасно разбирает текстовые метаданные. Обработка действует на интерфейс и Markdown, работает в dev и при статической сборке, не добавляет клиентский JS. Код, скрипты, URL и идентификаторы сохраняются. Регрессионные проверки типографирования входят в `npm run check`.

Официальные инструкции: [Astro](https://docs.astro.build/en/getting-started/), [Tailwind для Astro](https://tailwindcss.com/docs/installation/framework-guides/astro).

## Аналитика и документы

Яндекс.Метрика `113586660` подключается только после отдельного согласия посетителя. До выбора, при отказе, истечении срока/смене версии согласия и без JavaScript запросов к счётчику нет. Безусловный noscript-пиксель удалён. Clarity полностью удалён по команде владельца.

Компактное уведомление — узкая полоса во всю ширину снизу, около 48 px с удобными кнопками 44×44 px. «Да» и «Нет» имеют равный вес; прокрутка не считается согласием. «Настроить cookie» в подвале повторно открывает выбор. Решение хранится в localStorage 180 дней; при запрете хранилища применяется только к текущей странице. Отзыв прекращает новые обращения, очищает доступные записи Метрики своего домена и перезагружает страницу для выгрузки её кода. Обновление решения распространяется на открытые вкладки. Данные, уже отправленные поставщику, не удаляются одним нажатием в браузере.

На localhost счётчик не запускается даже после согласия. Версия и время положительного согласия передаются в параметрах визита. Это не отдельный независимый журнал согласий на собственном сервере: такого сервера у сайта нет.

ID, версия и срок согласия, ФИО и статус оператора — в `src/config/site.ts`; почта по вопросам данных — `links.privacyEmail`. Маршруты `/privacy/`, `/cookies/`, `/consent/` содержат политику обработки данных, cookie и отдельное согласие. Форм, заявок и рассылок на сайте нет. Smoke исполняет код готовой сборки без сети и проверяет выбор, отказ, отзыв, срок, ошибочное/недоступное хранилище и вкладки.

Технические изменения не подтверждают полное юридическое соответствие: вопросы уведомления РКН, локализации и инфраструктуры рассматриваются отдельно. [Описание и ограничения](docs/guides/PRIVACY.md).

## GitHub

Публикация выполняется только после отдельного разрешения владельца на push. Workflow проверяет `npm ci`, `check`, `build`, `smoke`; передаёт только `dist` и разрешает deploy только из `main`. Деплой имеет отдельные минимальные права. Никакие токены и `.env` для запуска не нужны.

Однократные настройки владельца:

1. Settings → Pages → Build and deployment → Source: GitHub Actions.
2. Проверить Secret scanning, Push protection и Dependabot alerts, включить 2FA учётной записи.
3. При желании настроить обновления зависимостей через проверяемые pull request.

Для собственного домена `agubanovv.ru` настроены Astro site, корневой base и CNAME. DNS-записи и финальная проверка HTTPS описаны в `docs/guides/DOMAIN_LATER.md`. DNS меняет владелец самостоятельно.

Фактическая проверка опубликованного адреса и запуска Actions возможна после разрешённого push. Lighthouse-оценки не заявляются без измерения.

Статьи и кейсы находятся в общем блоге и открываются только по адресу `/blog/имя-файла/`; адрес от корня сайта запрещён. Карточки, canonical, хлебные крошки и sitemap используют этот адрес. Ранее опубликованные статьи с корневых адресов перенесены в `/blog/`, на старых адресах сборка оставляет только страницы перенаправления.
