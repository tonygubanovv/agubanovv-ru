# Где что менять

Начните с задачи в таблице. Для обычного редактирования не нужно разбираться во всех папках.

Проверки и дальнейшее продвижение: [полный SEO-чек-лист](SEO_CHECKLIST.md).

| Хочу изменить | Открыть от корня проекта |
| --- | --- |
| Title, description, ключевые фразы любой страницы | `content/seo.md` — общая таблица |
| Текст статьи или кейса, заголовок, дату, теги | `content/blog/название-статьи/index.md` |
| Обложку и иллюстрации статьи | ту же папку `content/blog/название-статьи/` |
| Портрет | `content/images/anton-gubanov.png` |
| Имя, контакты, первый экран, «Обо мне», меню, рекомендации | `src/config/site.ts` |
| Язык и страна аудитории | `site.locale` в `src/config/site.ts`: русский (Россия), RU |
| Пункты меню и SVG-иконки | `mainMenu` в `src/config/site.ts`; общая разметка и hover — `src/components/MenuLinks.astro`, SVG — `src/components/Icon.astro`, раскрытие — `Header.astro` |
| Закрыть страницу от поиска | `site.search` в `src/config/site.ts` — только по решению владельца |

| Раздел «Навыки» (`/skills/`) | `src/pages/skills.astro` — разметка и оформление; `skillGroups` в `src/config/site.ts` — названия и навыки |
| Раздел «Рекомендую» (`/recommend/`) | `src/pages/recommend.astro` — оформление; `recommendations` в `src/config/site.ts` — названия, описания и ссылки |

## Три основные папки

```text
content/                        материалы для редактирования
  seo.md                        все SEO-метаданные одной таблицей
  blog/
    llms-txt-useless/            одна публикация = одна папка
      index.md                  текст и параметры публикации
      *.png                     её обложка и иллюстрации
    salesbot-utm-amocrm/
    telegram-ads-ib-vendor/
  images/                       общие фотографии для страниц

src/                            код, собирающий сайт
  config/site.ts                общие тексты и настройки
  pages/                        только текущие страницы
    legal/                      все юридические документы
    blog/                       лента, темы и шаблон адресов статей
    recommend.astro             раздел рекомендаций
    skills.astro                навыки
  layouts/                      оболочка, шаблон статьи и перенаправлений
  components/                   повторяющиеся элементы
  styles/global.css             оформление и темы
  utils/                        служебная логика: ссылки, SEO, даты
  content.config.ts             правила проверки публикаций
  middleware.ts                 автоматическая типографика HTML

docs/                           инструкции
  guides/                       как работать с сайтом
  agents/                       все инструкции, требования и промпты агентов
```

`content` означает «материалы», `pages` — «страницы», `layouts` — «шаблоны», `components` — «общие элементы», `utils` — «служебные функции». Имена папок кода оставлены привычными для Astro: они помогают инструментам и следующему разработчику ориентироваться в проекте.

`pages` не хранит копии статей. Файл `src/pages/blog/[slug].astro` — одна инструкция: взять каждую статью из `content/blog/` и оформить общим шаблоном. Сайт сам создаёт нужное количество страниц. Имя папки статьи задаёт её адрес: `content/blog/llms-txt-useless/index.md` → `/blog/llms-txt-useless/`. Переименование опубликованной папки меняет адрес; нужен редирект со старого адреса.

Для визуальной работы с материалами используйте [MarkText: инструкция для этого проекта](VISUAL_EDITING.md).

## Как редактировать SEO-таблицу

Откройте `content/seo.md` и найдите нужный адрес. В редакторе с Markdown-превью это обычная таблица; в исходнике ячейки разделены символом `|`.

- **Title** — точный заголовок вкладки, поиска и превью ссылок. Имя автора автоматически не добавляется.
- **Description** — описание для поиска и превью ссылок. Оно не меняет вступление статьи.
- **Ключевые фразы** — необязательное поле через запятую. Если заполнено, сайт добавляет `meta keywords`; пустое поле не выводится. Само заполнение поля не гарантирует продвижения.

Не переносите одну строку таблицы на несколько строк. Если в тексте нужен символ `|`, напишите `\|` или `&#124;`. Кавычки и запятые можно писать как обычно. SEO-тексты автоматически проходят типографику, как и остальной сайт.

Старые адреса документов `/privacy/`, `/cookies/`, `/consent/` перенаправляют на соответствующие `/legal/…/`. Исходники документов находятся только в `src/pages/legal/`; отдельных страниц-дублей в корне `pages/` нет. Все прежние адреса задаёт `movedPaths` в `src/utils/routes.ts`, их оформляет один `src/layouts/RedirectLayout.astro`. Перенаправления работают в разработке и в сборке, имеют `noindex` и отсутствуют в sitemap. Страницы перенаправлений создаются автоматически. Canonical, robots, обложки, подтверждения поисковых систем и технические метатеги формируются кодом; их не нужно повторять в таблице. Индексация управляется прежним блоком `site.search`.

## Как добавить статью

1. Создать папку `content/blog/короткое-имя-латиницей/`.
2. Внутри создать `index.md` и положить изображения рядом.
3. В начале файла заполнить параметры по образцу существующей статьи. `title` — заголовок на странице, `summary` — текст под ним и в карточках. Метаданные SEO здесь не задаются.
4. Обложку подключить в `cover.src` как `./имя-файла.png`; в тексте картинку — `![Описание](имя-файла.png)`.
5. Добавить строку `/blog/короткое-имя-латиницей/` в `content/seo.md`. Если появился новый раздел тегов, добавить строку для его страницы тоже.
6. Запустить `npm run check`, `npm run build`, `npm run smoke`. Просмотреть сайт через `npm run preview`. Публиковать только отдельной командой владельца.

Сборка остановится, если у страницы нет строки в SEO-таблице. Smoke-проверка также заметит опечатку в адресе таблицы, потерянную статью, картинку или ссылку.

## Остальные папки

| Папка | Для чего |
| --- | --- |
| `public/` | favicon, общая картинка превью, CNAME и публичные файлы проверок; копируются без преобразования |
| `scripts/` | автоматические проверки сборки и тесты |
| `.github/workflows/` | проверка и публикация на GitHub Pages |
| `.qoder/rules/` | правила для второго редактора |
| `node_modules/` | установленные зависимости; создаёт npm, руками не редактировать |
| `.astro/` | временные данные Astro; создаются автоматически |
| `dist/` | готовый сайт; пересоздаётся сборкой, правки делать в исходниках |

Файлы `package.json`, `package-lock.json`, `astro.config.mjs` и `tsconfig.json` отвечают за инструменты сборки. Для правки текста или SEO их открывать не нужно. Черновики, пароли и приватные документы в публичном проекте не хранить.

## Инструкции для ИИ и поисковики

Все содержательные правила для агентов собраны в `docs/agents/`: основные правила, безопасность, требования и промпты. В корне `AGENTS.md` и в `.qoder/rules/` остаются только ссылки на эту папку для автоматического обнаружения.

Документация не входит в сайт. GitHub Pages получает только `dist/`; `npm run smoke` блокирует появление документации, исходных Markdown-файлов, ссылок на инструкции и их адресов в sitemap. На домене сайта эти файлы не публикуются. Репозиторий GitHub остаётся публичным: его документы доступны отдельно от сайта, и запретить их индексацию настройкой сайта нельзя.
