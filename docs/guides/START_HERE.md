# Как работать с сайтом

Сайт уже создан на Astro. Основной помощник — Codex; Qoder и другие инструменты работают с тем же репозиторием по единым правилам. Писать код владельцу не требуется.

Начните с [карты проекта](PROJECT_MAP.md): там указано, какой файл открывать для каждой задачи. Все SEO-метаданные находятся в [одной таблице](../../content/seo.md), статьи — в `content/blog/`, по отдельной папке с картинками на публикацию.

## Повседневная работа

1. Откройте папку проекта в Codex или Qoder.
2. Обычными словами опишите изменение. Агент читает корневой AGENTS.md и документы в docs/specs/.
3. Агент меняет сайт, запускает проверки и открывает локальный результат.
4. Посмотрите результат. Для публикации дайте прямую команду: «Проверь и опубликуй эти изменения».
5. Агент делает commit и обычный push в main. GitHub Actions проверяет и публикует готовую сборку.

Не поручайте двум инструментам одновременно менять одни файлы. Перед сменой инструмента дождитесь завершения работы первого. Новый агент должен сохранить незакоммиченные изменения, а не сбрасывать их.

## Какие данные передать позже

- Имя и короткое профессиональное описание для сайта.
- Подтверждённые контакты: Telegram, email и другие ссылки.
- Готовые статьи, кейсы, изображения и разрешённые к публикации результаты.
- Если нужна аналитика — ID Метрики и согласованный порядок информирования посетителей.

Черновики храните в Google Docs, вне публичного репозитория. Готовую статью передайте агенту текстом или Markdown с изображениями. Примеры запросов находятся в docs/prompts/.

## Локальный просмотр

Агент выполняет npm ci при первой установке, затем npm run dev. Обычный адрес: http://127.0.0.1:4321/. Если порт занят, фактический адрес появится в терминале. Можно просто попросить агента: «Запусти сайт и открой его».
