# Поиск: Яндекс, Google и Bing

Страница о том, что уже сделано в коде и что осталось сделать владельцу руками. Порядок публикации — в [Публикации](PUBLISH.md), домен и DNS — в [Домене](DOMAIN_LATER.md).

## Что уже готово на стороне сайта

- **Подтверждение владения.** В `<head>` всех страниц стоят три мета-тега: `yandex-verification`, `google-site-verification`, `msvalidate.01`. Значения выданы самими сервисами и лежат в `site.verification` (`src/config/site.ts`); печатает их `src/components/SEOHead.astro`. Это публичные токены, а не секреты.
- **Карта сайта.** `https://agubanovv.ru/sitemap.xml` — список всех индексируемых страниц с реальными датами публикации и приоритетами; в панели вебмастера открывать нужно именно этот адрес. Служебные `sitemap-index.xml` и `sitemap-0.xml` тоже остаются в сборке, но ссылаться везде следует на `sitemap.xml`. Правила — в `src/utils/sitemapMeta.ts`.
- **robots.txt.** `https://agubanovv.ru/robots.txt`: общий блок и отдельный блок для Яндекса с `Clean-param` (UTM, mtm, клик-метки рекламных сетей, маркеры пересланных ссылок), чтобы размеченные ссылки не создавали дублей в индексе. Тот же текст в отдельной копии `/robots-yandex.txt` — для проверки; сам Яндекс читает только корневой файл. Оба файла печатает один источник — `src/utils/robots.ts`.
- **Хлебные крошки и разметка.** На каждой индексируемой странице цепочка «Главная → раздел → страница» с короткими русскими названиями и структурированные данные `BreadcrumbList`; статьи несут `BlogPosting`, кейсы — `Article` с реальными датами.
- **Юридические страницы закрыты от поиска.** `/legal/` и сами документы, а также старые адреса `/privacy/`, `/cookies/`, `/consent/` имеют `noindex, follow`, запрещены директивой `Disallow` и отсутствуют в карте сайта. Для посетителя они работают как раньше.
- **Список закрытых страниц ведёт владелец.** Кроме юридических документов он может закрыть любую страницу или раздел — см. [Как закрыть страницу от поиска](#как-закрыть-страницу-от-поиска).

## Что нужно сделать владельцу

1. **Включить HTTPS.** Сейчас GitHub Pages отдаёт для `agubanovv.ru` сертификат `*.github.io`, браузер показывает предупреждение. Пока это так, ни один поисковый сервис владение не подтвердит. Settings → Pages → Build and deployment: дождаться выпуска сертификата для домена и включить **Enforce HTTPS**.
2. **Яндекс.Вебмастер** — `https://webmaster.yandex.ru/`: добавить сайт, выбрать способ «Мета-тег», дождаться подтверждения. Затем в разделе «Индексирование → Карта сайта» указать `https://agubanovv.ru/sitemap.xml`, проверить `robots.txt`.
3. **Google Search Console** — `https://search.google.com/search-console`: добавить ресурс `https://agubanovv.ru` (домен или префикс URL), способ «Мета-тег». После подтверждения отправить sitemap и проверить отчёт «Индексирование → Страницы».
4. **Bing Webmaster Tools** — `https://www.bing.com/webmasters`: подтвердить через мета-тег, отправить карту сайта. Google частично использует индекс Bing, отдельная задача не критична.
5. Через 1–2 недели проверить, что главная и статья появились в поиске, а юридические страницы — нет.

## Что важно знать

- Подтверждение владения — это не «сайт проиндексирован». Оно только открывает доступ к отчётам.
- Пока страница запрещена и `noindex`, и `Disallow`, робот не может зайти на неё и увидеть `noindex`. Формально такой URL может остаться в выдаче одной строкой без описания. Поэтому страницы, закрытые владельцем, `Disallow` не получают — робот заходит, читает `noindex` и убирает адрес из результатов. У юридических документов запрет обхода остаётся: они не участвуют в поиске по другой причине и никогда не были в индексе.
- `Clean-param` понимает только Яндекс. Google опирается на canonical, который стоит на каждой индексируемой странице.
- Даты в карте сайта берутся из `date` и `updated` в статьях. Выдумывать «обновлено» ради свежести в выдаче запрещено.
- Агент не может подтвердить владение и включить HTTPS: это настройки аккаунта GitHub и поисковых сервисов. Отчёт о готовности пишется только после фактической проверки живого URL.

## Как проверить самому

Открыть в браузере и убедиться, что предупреждения о сертификате нет:

- `https://agubanovv.ru/robots.txt` — должны быть блоки `User-agent: *` и `User-agent: Yandex`, строка `Sitemap:`;
- `https://agubanovv.ru/sitemap.xml` и `https://agubanovv.ru/sitemap-0.xml` — список страниц с датами;
- `https://agubanovv.ru/legal/privacy/` — в исходном коде `<meta name="robots" content="noindex, follow">`;
- `https://agubanovv.ru/blog/…` — в начале `<main>` видны хлебные крошки.

После любой правки SEO-файлов локально: `npm run build` и `npm run smoke` — проверки в `scripts/check-dist.mjs` ловят рассогласование robots, sitemap, `noindex` и крошек.

## Как закрыть страницу от поиска

Владелец делает это сам, в одном месте — `src/config/site.ts`, блок `search`:

```ts
search: {
  indexingEnabled: true,
  closed: ['https://agubanovv.ru/blog/telegram-ads-ib-vendor/'],
},
```

- `closed` — список адресов, которые не должны показываться в поиске. Адрес вставляется ровно так, как он выглядит в браузере; можно короче: `/blog/telegram-ads-ib-vendor/`. Закрывается и целый раздел: достаточно написать `blog/`.
- Закрытая страница по-прежнему открывается посетителю по ссылке и остаётся в ленте блога и в карточках — поисковик просто перестаёт её показывать.
- Чтобы вернуть страницу в поиск, строку нужно удалить. Пустой список пишется так: `closed: []`.
- После правки — `npm run build` и `npm run smoke`, затем публикация. Проверка не пропустит опечатку в адресе и случайную страницу, которая получила `noindex` вне списка.
- `indexingEnabled: false` закрывает весь сайт разом: каждая страница получает `noindex, follow`, карты сайта пустые. Оба переключателя — только со слов владельца.
