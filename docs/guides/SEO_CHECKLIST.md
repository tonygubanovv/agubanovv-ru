# SEO: техническая база и дальнейшая работа

Аудит 23.10.2026. Статусы ниже разделяют проверенный код, ответы живого сайта и задачи в кабинетах. Настройки индексации владельца не менялись. Сведения о результатах поиска и позициях без доступа к кабинетам не подтверждены.

## Техническая база

| Проверка | Состояние и действие |
| --- | --- |
| HTTPS, сертификат публичного домена | Проверен успешный HTTPS-запрос; Cloudflare. Состояние origin-сертификата — отдельная задача из DOMAIN_LATER.md |
| HTTP → HTTPS | Проверен 301 на основной HTTPS-адрес |
| www → без www | Проверен 301 на https://agubanovv.ru/ |
| Настоящая 404 | Случайный несуществующий URL возвращает HTTP 404 |
| Статический контент | Статьи и ссылки находятся в HTML без выполнения JavaScript |
| Единый основной URL | Canonical с HTTPS и завершающим слэшем; smoke проверяет точное совпадение с адресом страницы |
| Уникальные title и description | Общая таблица content/seo.md; дубли индексируемых страниц останавливают smoke |
| Один H1, язык, заголовки | Один H1 и lang=ru проверяются; заголовки статей формируют содержание |
| Sitemap | Только существующие открытые страницы, включая /recommend/; проверка соответствия в обе стороны |
| Реальные даты | lastmod из публикаций, dateModified из updated или даты публикации; без подстановки даты сборки |
| robots.txt | Открывает контент и ресурсы; Clean-param только для Яндекса |
| Исключения из поиска | Сохраняются правила владельца: кейс ИБ-вендора закрыт, юридические страницы вне sitemap |
| Параметры ссылок | Canonical без меток, Clean-param для Яндекса; параметрические URL не включаются в sitemap |
| Старые адреса | HTML-перенаправления с canonical и noindex; при возможности настроить настоящие 301 на уровне Cloudflare отдельной задачей |
| Внутренние ссылки | Навигация, темы, хлебные крошки, связанные публикации; локальные файлы проверяются smoke |
| Favicon | SVG и настоящий ICO 16/32/48 px; проверка файла и подключения |
| Превью ссылок | Open Graph и Twitter; JPEG обложки для внешних роботов |
| Крупные изображения в поиске | max-image-preview:large на открытых страницах |
| Структурированные данные | WebSite, Person, BlogPosting и BreadcrumbList; автор связан с видимым блоком «Обо мне» |
| Автор и даты на странице | Видимая ссылка на автора, дата публикации и дата фактического обновления |
| Изображения | Astro/sharp, варианты ширины, alt, размеры, lazy loading вне первого экрана |
| Мобильная версия | Адаптивные стили есть; после изменений нужен визуальный просмотр и проверка переполнений |
| Скорость | Статика, локальные шрифты, оптимизация картинок; баллы Lighthouse и реальные CWV ещё не измерены |
| Аналитика | Метрика только после согласия; технические проверки согласия проходят |
| Реферальные ссылки | rel=sponsored в рекомендациях, безопасное открытие в новой вкладке |
| Автоматический контроль | npm ci, check, build, smoke до публикации; публикация только dist |

## Приоритет 1: поисковые кабинеты и измерения

1. В Google Search Console, Яндекс.Вебмастере и Bing проверить подтверждённое владение. Установленные мета-теги сами по себе не доказывают подтверждение. Инструкция — SEARCH_ENGINES.md.
2. В каждом кабинете отправить https://agubanovv.ru/sitemap.xml и проверить, что карта успешно прочитана, а не просто добавлена.
3. Проверить главную, блог, рекомендации и каждую открытую статью инструментом проверки URL: доступ робота, выбранный canonical, запреты, дата обхода, результат рендеринга.
4. Запросить переобход изменённых страниц. Для Bing и Яндекса можно подключить IndexNow отдельной задачей: публичный ключ уже есть. Не отправлять в него закрытые страницы.
5. Проверить ручные меры, безопасность, исключённые страницы, дубли и отчёты об обходе. Сравнивать число индексируемых URL с sitemap; оператор site: не заменяет отчёт кабинета.
6. Проверить разметку статей через Google Rich Results Test и Schema Markup Validator. Синтаксическая проверка сборки не доказывает доступность расширенного результата.
7. Измерить мобильную главную и статью в PageSpeed Insights. По реальным полевым данным на 75-м перцентиле ориентиры CWV: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1. У нового сайта данных может ещё не быть; лабораторный Lighthouse — отдельный замер.
8. Проверить на узком экране обе темы, переносы, меню, содержание, фокус, доступность текста и отсутствие перекрытия контента cookie-полосой.
9. Проверить Cloudflare: поисковые роботы не должны получать CAPTCHA, 403, 429 или заглушку вместо HTML; не ослаблять защиту вслепую.

## Приоритет 2: контент и поисковый спрос

1. Собрать реальные запросы из Вордстата и кабинетов, сгруппировать по задаче читателя: Telegram Ads, UTM/amoCRM, SEO/GEO, инструменты ИИ. Один основной замысел — одна страница; не делать клоны под вариации запроса.
2. Составить таблицу «запрос → намерение → существующая страница → следующий материал». Проверить выдачу вручную: формат результатов, полноту ответа и конкурирующие страницы. Частотности не выдумывать.
3. Уточнять title и description по содержанию и данным показов, избегать одинаковых сниппетов и обещаний, которых нет в статье. Длина в символах — ориентир, а не жёсткий фактор ранжирования.
4. Добавлять в статьи оригинальные примеры, скриншоты, воспроизводимые шаги, ограничения и ссылки на первоисточники. Факты, результаты и опыт — только подтверждённые владельцем.
5. Связывать статьи контекстными ссылками с понятными названиями. Страницы тем развивать по мере появления материала, не заполнять искусственным текстом ради объёма.
6. Пересматривать устаревшие инструкции; дату обновления менять при реальном содержательном изменении. Для снятых материалов выбирать 404/410 или релевантное перенаправление, а не отправлять всё на главную.
7. Укреплять сведения об авторе реальным опытом и доступными контактами. Не добавлять вымышленные отзывы, рейтинги, организации или награды в текст и разметку.

## Приоритет 3: рост и сопровождение

- Снимать исходную точку: открытые и индексируемые URL, показы, клики, CTR, запросы, страницы входа и целевые переходы к контактам. Фиксировать дату релиза.
- Сравнивать сопоставимые периоды по 28 дней с учётом сезонности и страны/устройства; при малых данных не делать выводов по единичным показам.
- Раз в месяц: ошибки обхода, индексация, CWV, изменение запросов, устаревший контент и битые внешние ссылки. После каждого релиза: статусы страниц, canonical, sitemap и 404.
- Получать естественные упоминания через полезные статьи, профессиональные сообщества и реальные кейсы. Не покупать ссылочные сетки и не накручивать поведенческие сигналы.
- Если нужен постоянный мониторинг, согласовать отдельную автоматизацию с уведомлениями только о существенных проблемах.

## Что не является обязательной базой

Не добавлять ради галочки meta keywords, FAQ/Review-разметку без подходящего видимого контента, фиктивный SearchAction, AMP, hreflang без переводов или массовые страницы под ключи. Файл llms.txt не заменяет доступный HTML, индексацию и полезный контент. Sitemap, разметка и техническое здоровье не гарантируют позиции или индексацию.
