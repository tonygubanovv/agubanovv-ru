# Техническое задание — личный сайт (v1.0)

Статус: утверждённые требования. Дата: 22.10.2026.

## 1. Цель

Построить полностью новый персональный сайт для специалиста по digital-маркетингу с главным экраном, портфолио проектов/кейсов и блогом. Посетители — коллеги, маркетологи и IT-специалисты, преимущественно из РФ. Владелец не программист; основной инструмент разработки — Codex, дополнительный — Qoder, статьи писать в Google Docs.

Проект должен быть быстро загружаемым, визуально современным, адаптивным, готовым к органическому поисковому трафику, безопасным для публичного GitHub и простым в сопровождении. Запуск без серверной части и каких-либо платных сервисов.

## 2. Платформа и жизненный цикл

- Существующий публичный репозиторий: `https://github.com/tonygubanovv/agubanovv-ru`.
- Публикация по согласованному собственному адресу: `https://agubanovv.ru/`.
- Исходники публичные, сайт собирается в статические файлы и публикуется через GitHub Actions (ветка `main`).
- При первом запуске удалить ВСЕ старые файлы сайта, включая старые конфиги Next.js, assets, содержимое и прежние workflow. Не переносить существующий дизайн, копирайтинг, функциональность или страницы.
- Не создавать backup и отдельную rollback-точку. Не удалять сам Git-репозиторий и не переписывать его историю. Не стирать папку `.git`.
- Сохранить новые файлы инструкций из этого комплекта, подключить новое приложение.
- Никакой админки, пользовательских аккаунтов, комментариев, форм, серверного рендеринга, API-сервера и базы данных.

## 3. Стек

- Astro, актуальная стабильная совместимая версия; `output: 'static'`.
- TypeScript, строгая конфигурация, `astro check`.
- Tailwind CSS 4 с Vite-плагином. Для тем, дизайн-токенов, состояния компонентов — CSS custom properties. Каталог `docs/` исключён из сканера классов (`@source not` в `src/styles/global.css`): без этого одно слово в спецификации добавляет utility-класс в CSS всех страниц.
- Astro Content Collections с `glob` loader и схемой Zod для `blog` и `projects`. `.md` по умолчанию, `.mdx` только для публикаций со специальными компонентами.
- Официальные интеграции `@astrojs/sitemap` и (при необходимости MDX) `@astrojs/mdx`.
- Статическая генерация, без React/Vue/Svelte на старте. Для переключения темы — небольшой клиентский скрипт.
- `npm`, один `package-lock.json`, совместимая Node.js 24 LTS.
- Без тяжёлых UI-библиотек и дополнительных зависимостей «на будущее».

## 4. Страницы и маршруты

Обязательно:
1. `/` — главная: выразительный первый экран с понятным профессиональным позиционированием, блок «Обо мне / Чем занимаюсь», подборка проектов (если опубликованы), последние статьи (если опубликованы), ссылки на соцсети и способы связаться без форм.
2. `/projects/` — карточки кейсов; при отсутствии кейсов — аккуратное пустое состояние без выдуманных проектов.
3. `/projects/[slug]/` — полноценный кейс, если в коллекции есть материалы; структура: задача, роль, подход, процесс, результат (только подтверждённые данные), изображения с подписями, связанные материалы.
4. `/blog/` — лента статей: карточка из обложки, даты, заголовка и описания, лента тем над карточками, пустое состояние.
5. `/blog/[slug]/` — статья с датой, категорией, тегами, оглавлением для длинных статей, сносками/ссылками, удобной шириной текста, блоком «назад к статьям» и возможными связанными публикациями.
6. `/blog/tags/[tag]/` — статические страницы тегов (если есть публикации с тегом); не вводить клиентский JS ради фильтрации.
7. `/404.html` — отдельная 404-страница со ссылкой на главную.

`/about/` как отдельная страница не нужна в v1: информация о владельце на главной. Поиск по статьям, RSS и email-подписка не нужны.

## 5. Контент и конфигурация

- Имя, должность, описание, контакты, соцсети, навигацию и параметры сайта держать централизованно в `src/config/site.ts`.
- Не выдумывать достижения, опыт, личные факты, бренды клиентов и числовые результаты. Если нет достоверных данных: нейтральные формулировки и placeholders в конфиге, которые владелец заполнит позже. Не показывать на живом сайте `TODO`, `[ИМЯ]` и фальшивые кейсы.
- Допустимые контакты: Telegram и email через `mailto:` после предоставления. Контакты задаются один раз в объекте `links` файла `src/config/site.ts`, компоненты используют общие значения. Личный GitHub владельца на сайте не показывать. Никаких форм.
- Статьи и кейсы отдельными Markdown/MDX-файлами. Строгая типизированная frontmatter-схема.
- Не создавать публичные черновики в GitHub. Владелец продолжает хранить их в Google Docs до публикации.
- Для даты поста задать однозначный формат ISO `YYYY-MM-DD`, для всех публичных временных меток согласованную часовую зону; даты выводить по-русски.
- Сортировка статей и кейсов по дате, стабильно работающая при равенстве дат.

## 6. Дизайн и UX

Подробности в `DESIGN_SYSTEM.md`. Важное:
- Современная технологичная эстетика без шаблонного «AI-лендинга», хорошая типографика и понятная иерархия.
- Светлая и тёмная темы; системная тема по умолчанию, ручной переключатель и сохранение выбора на устройстве.
- Полная адаптивность от 360 px; меню, карточки, длинные заголовки и таблицы должны работать на телефоне.
- Плавные микроанимации и hover-эффекты. CSS-first, `prefers-reduced-motion`.
- Изображения оптимизировать средствами Astro, задавать width/height либо aspect ratio, использовать lazy loading там, где уместно.
- Не загружать внешние шрифты через CDN без необходимости, использовать self-hosting или системные шрифты.

## 7. SEO

- Статический HTML каждой страницы доступен поисковым роботам без выполнения JavaScript.
- Настроить уникальные `title`, `description`, один H1, корректную структуру H2/H3, canonical URL, Open Graph/Twitter metadata.
- Добавить `sitemap.xml` через официальную интеграцию, `robots.txt` с правильным адресом sitemap, favicon, иконку для соцсетей. Карта сайта содержит только реально существующие индексируемые страницы, даты — из frontmatter публикаций; правила `lastmod` и приоритетов описаны в [Контент и SEO](CONTENT_AND_SEO.md).
- `robots.txt` генерируется из одного источника (`src/utils/robots.ts`) и содержит блок для всех роботов и отдельный блок для Яндекса с `Clean-param`; директивы, отсутствующие в документации поисковых систем (`Host`, `Crawl-delay`, `Noindex`), не применять.
- На страницах статей — корректный JSON-LD BlogPosting, на кейсах — Article; на индексируемых страницах `BreadcrumbList`, согласованный с видимыми хлебными крошками; на главной при наличии подтверждённых данных — Person/Website. Не размечать фиктивные данные.
- Страницы согласий и политик остаются доступными по прямым ссылкам, но закрыты от поиска: `noindex` + `Disallow` + отсутствие в sitemap (`legalPaths` в `src/utils/routes.ts`). Отдельные страницы сверх них закрывает владелец списком `search.closed` в `src/config/site.ts`: `noindex` без `Disallow`, чтобы робот прочитал запрет, плюс отсутствие в sitemap.
- Русский язык `lang="ru"`; возможность добавить английский позднее без смены русских slug/URL. Не создавать пустые англоязычные разделы и `hreflang` до реальных переводов.
- Для внешних ссылок в новой вкладке `rel="noopener noreferrer"`; не делать слепо все ссылки `target="_blank"`.
- Соцсети и внешнее видео через обычные ссылки по умолчанию; тяжёлые embed загружать только по действию пользователя/лениво.
- Яндекс.Метрика: подготовить компонент/интеграцию с выключенным по умолчанию режимом, если ID не предоставлен. Не подставлять выдуманный ID. Включить после согласования номера счётчика, политики использования cookie и уведомления о приватности.
- Заложить отсутствие внешнего JS, если он не нужен; не делать SPA-навигацию на старте.

## 8. Собственный домен GitHub Pages — критично

В `astro.config.mjs`:

```js
import { defineConfig } from 'astro/config';
import tailwindcss from '@tailwindcss/vite';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://agubanovv.ru',
  base: '/',
  trailingSlash: 'always',
  output: 'static',
  // sitemap(): filter убирает 404 и закрытые от индексации страницы,
  // serialize добавляет реальные lastmod и приоритеты из src/utils/sitemapMeta.ts.
  // Плагин sitemap-public-alias записывает в sitemap.xml список страниц, а не индекс.
  integrations: [sitemap({ filter, serialize })],
  vite: { plugins: [tailwindcss()] },
});
```

Полный рабочий конфиг — в `astro.config.mjs`; здесь оставлены только неизменяемые настройки домена.

- Для всех внутренних ссылок использовать единый утилитарный метод, учитывающий `import.meta.env.BASE_URL` и окончательные слэши; не склеивать URL по-разному в компонентах.
- Для локальных ссылок и ассетов использовать общую утилиту с `BASE_URL`. Текущий base `/`, префикса `/agubanovv-ru/` в новых URL нет.
- Canonical, OG URL, ссылки из sitemap и `robots.txt` должны использовать `https://agubanovv.ru/`.
- Для изображений/видео в `public` корректно учитывать базовый путь. Изображения из `src/assets` импортировать через Astro по правилам Astro assets и выводить компонентом `astro:assets`, а не голым `<img src>`: сборка пережимает их через `sharp` и отдаёт браузеру вариант по ширине (WebP, качества 72–75). Сервис `astro/assets/services/noop`, который отдавал браузеру исходники по 2,7 МБ, отключён по прямому решению владельца от 22.10.2026 и не должен появляться снова.
- `npm run dev` и `npm run preview` должны работать локально; итоговую сборку проверить smoke-тестом `scripts/check-dist.mjs`.
- `public/CNAME` содержит согласованный домен `agubanovv.ru`. GitHub Pages использует GitHub Actions.

## 9. Публикация

- GitHub Actions запускается на push в `main` (и вручную). Перед деплоем обязательны `npm ci`, `npm run check`, `npm run build`, `npm run smoke`.
- Публиковать ТОЛЬКО результат успешной сборки из `dist`, а не исходники.
- В GitHub -> Settings -> Pages -> Build and deployment -> Source установить GitHub Actions.
- Минимально необходимые permissions для GitHub Actions, без дополнительных токенов.
- Никаких серверных `NEXT_PUBLIC_*`, `.env` и secrets для обычного запуска.
- После публикации проверять прямое открытие главной, блога, проектов и 404 по правильному base-пути.

## 10. Что делать НЕ надо

Не создавать на старте: backend, серверный API, базу данных, авторизацию, комментарии, формы, CMS, поиск, многоязычные пустышки, RSS, карусели, аналитический dashboard, PWA, cookie banner без понятного сценария, React и зависимости ради одной CSS-анимации.

## 11. Этапы выполнения агентом

1. Удалить наследие старого сайта без backup; оставить `.git/` и новый комплект инструкций.
2. Инициализировать чистый Astro, зависимости и конфигурацию; добиться рабочей сборки.
3. Реализовать дизайн-токены, общие компоненты, темы, адаптивную навигацию.
4. Реализовать все обязательные страницы, Markdown коллекции, схемы и пустые состояния без фиктивного контента.
5. Настроить SEO, sitemap, robots, 404, картинки, доступность и анимации.
6. Проверить `base`, все локальные и производственные URL, собрать скрипты и автоматические проверки.
7. Финально визуально проверить светлую/тёмную темы на разных ширинах. Исправить ошибки и сообщить владельцу, как открыть сайт локально и опубликовать.

Каждая публикация открывается только по адресу `/blog/<slug>/`, где slug — имя файла; адрес от корня сайта запрещён, поле `permalink` и корневой маршрут удалены. Кейс Telegram Ads и инструкция Salesbot перенесены в `/blog/telegram-ads-ib-vendor/` и `/blog/salesbot-utm-amocrm/`; на прежних адресах сборка оставляет только страницы перенаправления из `movedPaths` (`src/utils/routes.ts`).
