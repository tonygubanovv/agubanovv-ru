# Безопасность и поддержка

## Что публично

В репозитории будут публичны код сайта, опубликованные Markdown-статьи и изображения, общие конфигурации и весь обычный Git history. GitHub Pages отдаёт публикуемые файлы всем посетителям. В браузерном JS нет секретов.

## Что никогда не коммитить

`.env`, `.env.local`, любые `.env.*` (кроме пустого `.env.example`), токены, ключи, пароли, `.pem`, `.p12`, сертификаты, API-ключи, документы клиентов, черновики, приватные переписки, дампы, личные настройки агентов.

`PUBLIC_*` и всякое значение, использованное для рендера клиентского кода, не может хранить секрет. GitHub Actions Secrets защищают входные значения на этапе сборки, но НЕ защищают содержимое уже сгенерированного HTML/JS.

## До первого коммита

1. Создать `.gitignore` из комплекта.
2. Убедиться, что никаких реальных `.env` и токенов не попало в индексацию Git (`git status --short`, staged list).
3. Не тащить старые проектные конфиги/ассеты в новую кодовую базу.
4. Не выдавать GitHub Actions избыточных прав; использовать `GITHUB_TOKEN` с `contents:read` для сборки и `pages:write`/`id-token:write` для деплоя.

## Настройки GitHub, которые владелец включает в интерфейсе

- Settings -> Pages -> Source: **GitHub Actions**.
- Settings -> Security & analysis / Code security: проверить Secret scanning и Push protection (названия могут меняться), не отключать защиту.
- Security -> Dependabot alerts: включить уведомления об уязвимостях.
- Включить обновление зависимостей через Dependabot только по pull request и проверять совместимость перед слиянием.
- 2FA для GitHub учётной записи и минимальные права токенов/приложений.
- Не использовать сторонние GitHub Actions без необходимости.

## Если секрет уже оказался в старой истории

Новое удаление файлов само по себе не удаляет старые коммиты. Если в истории есть секрет, его требуется отозвать и заменить. Полная очистка истории — отдельная рискованная операция, не выполнять её автоматически и не использовать `git push --force` без отдельного подтверждения.

## Поддержка

- Перед публикацией проводить локальные проверки.
- Не обновлять major-версии Astro/Tailwind/интеграций автоматически без проверки.
- Не вводить новые зависимости и внешние сервисы «на будущее».
- Следить за предупреждениями Dependabot и GitHub Actions.
- При добавлении мини-приложений выбирать статические вычисления в браузере; если понадобится приватный API — отдельно обсуждать backend и угрозы.
