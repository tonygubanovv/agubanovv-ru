# Редакционный набор

Один и тот же набор работает в трёх местах: на сайте (remark → rehype →
`@layer prose` в `src/styles/global.css`), в предпросмотре админки
(`calloutsToHtml` + `decoratePreviewHtml`) и в валидаторе
(`scripts/check-content.mjs`). Расхождение между ними — ошибка сборки.

## Директивы-контейнеры

Формы записи две, они эквивалентны:

```markdown
:::note[Пояснение]
Текст заметки.
:::

:::note{title="Пояснение"}
Текст заметки.
:::
```

Пробел после имени директивой не считается: `:::note Пояснение` не разбирается
ни remark, ни предпросмотром, и валидатор требует переписать его в скобки.
Открывающая и закрывающая строки начинаются с первого символа: отступ
превращает блок в обычный текст, поэтому нормализация в админке снимает до
трёх ведущих пробелов.

| Директива | Для чего | Что в HTML |
| --- | --- | --- |
| `:::note[Текст]` | пояснение, определение, контекст | `div.callout.callout-note` |
| `:::warn[Текст]` | частая ошибка, риск, ограничение | `div.callout.callout-warn` |
| `:::takeaway[Вывод]` | главная мысль блока | `div.callout.callout-takeaway` |
| `:::steps[Как считаем]` | порядок действий | `div.callout.callout-steps`, шаги нумеруются CSS |
| `:::details[Что под капотом]` | сворачиваемый подробный блок | `details.callout.callout-details` + `summary` |
| `:::quote[Кто сказал]` | выносная цитата | `blockquote.pull-quote` + `footer.pull-quote-attribution` |

Правила, которые проверяет валидатор:

- неизвестного имени директивы не существует — сборка падает с подсказкой;
- внутри `:::steps` обязан быть список (обычный или нумерованный);
- `:::quote` без автора в подписи не имеет смысла;
- блок не может быть пустым, подпись — длиннее 64 символов или оканчиваться
  точкой: это заголовок, а не предложение;
- директивы можно вкладывать друг в друга (на сайте; предпросмотр админки
  размечает только верхний уровень).

## Inline-выделение

`:mark[важное]` → `mark.inline-mark`. Других inline-директив нет, `:tip[` или
`:link[` валидатор считает опечаткой.

## Обычный markdown, на который есть стили

| Элемент | Синтаксис | Что делает сайт |
| --- | --- | --- |
| Таблица | GitHub-таблица с `|` | оборачивается в `div.table-wrap` — скролл по горизонтали на 360px, шапка остаётся видимой |
| Задача | `- [ ]` / `- [x]` | `ul.contains-task-list`, чекбокс стилизован под тему |
| Картинка с подписью | `![Что видно](/img/file.svg "Подпись")` | `figure.prose-figure` + `figcaption`, `title` из исходника удаляется, чтобы браузер не показывал тултип поверх подписи |
| Сноска | `[^1]` в тексте, `[^1]:` в конце | `sup` со ссылкой и `section.footnotes` с `aria-label="Примечания"`; обратная стрелка подписана «К сноске N». Служебный заголовок секции убран, чтобы не попадать в оглавление |
| Разделитель | `---` между абзацами | короткая линия-разделитель, не полоса на всю ширину |

Картинка без `title` остаётся просто картинкой. Требование к пути: `/` от
корня и файл обязан лежать в `public/` — валидатор проверяет его существование.

## Якоря

Идентификаторы заголовков генерирует `src/lib/slug.ts`, а не Astro: стандартный
slugger склеивает кириллицу и съедает неразрывные пробелы типографа. Правило
простое: транслитерация, дефисы, без повторов. Тот же модуль используют
содержание страницы и валидатор, поэтому ссылка вида `[приёмка](#priemka)`
не может разойтись с реальным `id`.

Проверяется: отсутствие пропуска уровня (`h2` → `h4`), уникальность якорей,
наличие цели у каждой внутренней ссылки `#…`.

## Что делает админка

При сохранении текст нормализуется (`src/lib/prose-normalize.ts`): `:::`
сдвигается к началу строки, старый формат заголовка директивы переводится в
скобки, снимается экранирование `[ ]` и `[^1]`, маркеры списков приводятся к
дефису, убираются двойные и хвостовые пробелы, схлопываются пустые строки.
Внутри блоков кода правки не выполняются. Список применённых правил админка
показывает в уведомлении — молча текст не переписывается.

Кнопки-подсказки над редактором вставляют каркас директивы по месту курсора;
они берутся из `directiveCheatSheet`, поэтому подсказка и валидатор всегда
перечисляют один и тот же набор.

## Как проверить

```bash
npm run check:content   # исходники и собранный dist
npm run verify          # типограф + правила + сборка + контент
```

Валидатор сверяет не только исходники, но и результат: сколько директив
объявлено, столько и должно дойти до HTML; каждое `<table>` обязано стоять в
`.table-wrap`, каждая картинка с подписью — в `figure`, каждый пункт задачи —
иметь чекбокс. Найденные в собранной странице `:::` означают, что блок не
разобрался.

Подробный разбор правил вёрстки — в `docs/DESIGN_RULES.md`.
