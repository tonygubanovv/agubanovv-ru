# Интерфейс, контент и релиз — всегда применять

- Дизайн: сдержанный технологичный стиль, аккуратная типографика, воздух, выразительные карточки, тонкие линии и мягкие градиенты. Подробности в `docs/agents/specs/DESIGN_SYSTEM.md`.
- Сначала создавай повторно используемые компоненты и токены, затем собирай страницы. Не допускай разрозненных визуальных решений.
- Полностью адаптивный интерфейс: проверяй 360, 768, 1280 и 1920 px; никакой горизонтальной прокрутки.
- Редакционный стиль: живой и конкретный русский язык, никаких фиктивных достижений и маркетинговой воды. Не переносить старые тексты.
- Блог и проекты заполняются из Content Collections. Черновики остаются вне GitHub; пустые списки должны выглядеть законченными.
- Текстовые публикации — только под адресом `/blog/<slug>/`, адрес от корня сайта запрещён. Смена адреса опубликованной статьи требует перенаправления со старого адреса.
- Индексацию меняет только владелец: общий переключатель `indexingEnabled` и список закрытых страниц `closed` в `src/config/site.ts`. Закрытая страница доступна посетителю, `noindex` без `Disallow`.
- Размер, отступ, скругление и зона нажатия — только из шкалы токенов в `src/styles/global.css`; голых чисел в CSS-правилах нет. Подпись над заголовком — `Kicker.astro`, техничная строка — класс `.meta`, карточка публикации = обложка, дата, заголовок, текст.
- Для простых эффектов используй CSS, JS — только если без него не обойтись. Уважай reduced motion.
- Любые изменения заканчивай проверками: `npm run check`, `npm run build`, `npm run smoke` и визуальным просмотром.
- Прежде чем написать «готово», перечисли реальные выполненные пункты и возможные ограничения.
