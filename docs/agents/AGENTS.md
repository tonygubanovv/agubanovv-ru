# AGENTS.md — обязательные правила проекта

Ты разрабатываешь личный сайт для человека без навыков программирования. Твоя цель — готовый, красивый, быстрый, безопасный и понятный в сопровождении продукт, а не демонстрация сложных технологий.

Основной агент владельца — Codex, дополнительный — Qoder. Эти правила обязательны для любого инструмента разработки. Все инструкции агентов, требования и готовые запросы находятся в `docs/agents/`; навигация — `docs/agents/README.md`. Руководства владельцу — в `docs/guides/`. В корне остаются стандартные точки входа `README.md` и `AGENTS.md`. `.qoder/rules/` — адаптер для Qoder, а не отдельное ТЗ.

## Перед любой работой
1. Прочитай `docs/agents/specs/TECHNICAL_SPEC.md`, `docs/agents/specs/DESIGN_SYSTEM.md`, `docs/agents/specs/CONTENT_AND_SEO.md`, `docs/agents/specs/SECURITY.md`, `docs/agents/specs/ACCEPTANCE.md`.
2. Применяй `docs/agents/SECURITY.md` и `docs/agents/DESIGN_AND_DELIVERY.md`. При противоречии уточняй решение, не молча меняй требования.
3. Пиши владельцу по-русски: коротко, простыми словами. Не перекладывай техническую работу на него.
4. Сначала коротко сформулируй план, затем реализуй и проверь результат. Не выдавай непроверенную работу за готовую.

## Статус проекта: чистый старт уже выполнен
- Старое приложение Next.js/React удалено из рабочего дерева по прямому решению владельца. Создан новый Astro-проект без переноса старого контента, без backup и отдельной точки восстановления.
- НЕ повторяй очистку при следующих задачах: поддерживай существующий Astro-сайт. `docs/agents/prompts/INITIAL_BUILD.md` — архив, не действующая команда на удаление.
- Не удаляй `.git/`, `AGENTS.md`, `.qoder/rules/`, `docs/`, `scripts/check-dist.mjs`, `.gitignore`, `.github/workflows/deploy.yml`.
- НЕ переписывай историю Git, НЕ делай `git push --force` и НЕ удаляй репозиторий. Очистка файлов не удаляет старые коммиты; если понадобится именно стирание истории, это отдельная операция с явным разрешением.
- Не изучай и не переноси сведения со старого сайта как источник текстов. Известные факты бери только из нового ТЗ и подтверждённых материалов владельца.

## Неизменяемая техническая основа
- Astro (актуальная стабильная совместимая версия), генерация статического HTML, `output: 'static'`.
- TypeScript, строгая проверка через `astro check`.
- Tailwind CSS 4 через `@tailwindcss/vite` (не ставь устаревший `@astrojs/tailwind`).
- Обычные `.astro` компоненты и CSS; без React, Next.js, серверного кода, базы данных, CMS или API-сервера.
- Markdown для блога и кейсов, MDX только для реально необходимой интерактивной публикации, Astro Content Collections с типизированной схемой.
- Любой опубликованный текстовый материал доступен только по адресу `https://agubanovv.ru/blog/<slug>/`. Адреса от корня сайта запрещены: поле `permalink` и корневой маршрут `src/pages/[slug].astro` удалены по прямому решению владельца, возвращать их нельзя. `npm run smoke` не пропустит публикацию вне `/blog/`.
- Сменить адрес уже опубликованной статьи можно только вместе с перенаправлением со старого адреса (`movedPaths` в `src/utils/routes.ts`); серверного 301 на GitHub Pages нет.
- Индексацией владеет владелец: общий переключатель `site.search.indexingEnabled` и список закрытых страниц `site.search.closed` в `src/config/site.ts`. Менять их и `legalPaths` можно только по его прямому слову. Закрытая страница остаётся доступной посетителю и в лентах: она получает `noindex, follow`, теряет canonical и исчезает из sitemap, но обход ей не запрещается — иначе робот не увидит `noindex`.
- `npm` и коммит `package-lock.json`. Не вводи другие пакетные менеджеры.
- GitHub Pages через GitHub Actions; публикация из `main` после успешных проверок.
- Текущий URL `https://agubanovv.ru/`. В `astro.config.mjs`: `site: 'https://agubanovv.ru'`, `base: '/'`, `trailingSlash: 'always'`.
- Домен `agubanovv.ru` согласован владельцем. `public/CNAME` содержит только `agubanovv.ru`; не менять домен без отдельного запроса.

## Качество кода
- Основной акцент — зелёный: `#7cff5a` в тёмной теме, контрастный `#2e731d` в светлой. Переключатель темы — минимальная иконка в подвале. Номера секций равны по размеру соседним заголовкам. Шапка закреплена, скрывается при прокрутке вниз и возвращается вверх. Оглавление публикаций — только в закреплённой левой колонке на широком экране, без блока внутри статьи.
- Hover кнопок и ссылок не меняет положение, размер или масштаб элемента: только цвет, фон, рамка и умеренная тень. У некликабельных карточек и других статичных элементов нет hover-анимаций. Декоративные анимации независимы от наведения и не мешают управлению.
- Основной шрифт — локальный Onest; код — локальный JetBrains Mono. Подписи и навигация используют Onest, без декоративного капслока и разрядки букв.
- Стрелки и другие пиктограммы — только SVG из общего `Icon.astro`, никогда текстовые символы. Новые семейства иконок без причины не добавлять.
- Все кегли, отступы, скругления и зоны нажатия берутся только из шкалы токенов в `src/styles/global.css` (`--text-1…7`, `--display-1…3`, `--space-1…9`, `--radius-*`, `--gutter`, `--measure`, `--tap`). Голое число внутри CSS-правила — ошибка: нужен новый размер, добавляй ступень. Подпись над заголовком рисует один `Kicker.astro`, техничную строку (дата, рубрика, редакция документа) — один класс `.meta`. Карточка публикации собирается ровно из обложки, даты, заголовка и описания — рубрика и теги в карточку не возвращаются.
- Любой человекочитаемый текст проходит автоматический Typograf при рендеринге HTML: интерфейс, Markdown, подписи, SEO и доступные названия. Код, URL, идентификаторы, скрипты и даты в машинном формате не менять. Проверять неразрывные пробелы на узких экранах.
- Контакты задавать только в объекте `links` в `src/config/site.ts`; повторные вхождения получают значение из него. Не вставлять вручную Telegram URL в компоненты и статьи. Не добавлять ссылку на личный GitHub владельца.
- Сначала используй возможности Astro и CSS; добавляй новую зависимость только при реальной необходимости, объяснив её назначение.
- Не переписывай соседние компоненты без причины; небольшие изменения делай локально.
- Не дублируй шапку, подвал, SEO или карточки между страницами: используй общие компоненты.
- Все постоянные данные о сайте и ссылки на соцсети — в `src/config/site.ts`, без выдуманных личных данных. SEO-метаданные страниц — исключение: только в `content/seo.md`.
- Все локальные URL (страницы, изображения, ассеты, навигация) должны корректно учитывать `import.meta.env.BASE_URL`. Не хардкодь адреса от `/` без базового префикса.
- Никаких заглушек вида `href="#"`, выдуманных кейсов, метрик и клиентских логотипов. Если реального контента пока нет — сделай законченный empty state.
- Все внешние ссылки: явный адрес, безопасный `rel` у новых вкладок.
- Сохраняй семантический HTML, клавиатурную навигацию, видимый фокус, осмысленные alt-тексты, контраст и `prefers-reduced-motion`.
- Тёмная/светлая тема по системной настройке + ручной переключатель, без резкой вспышки неправильной темы и без ошибок при отключённом JS.
- По умолчанию никаких тяжёлых 3D, каруселей, SPA-роутинга или анимационных фреймворков.

## Безопасность — приоритет над красотой
- НИКОГДА не публикуй секреты, `.env*`, токены, пароли, персональные черновики, приватные документы, ключи/сертификаты.
- Не считай `PUBLIC_*` секретным: оно попадает в клиентский код.
- Разрешена Яндекс.Метрика только после явного действующего согласия посетителя: до выбора, при отказе/отзыве и без JS нет трекера и noscript-пикселя. Clarity удалён по прямой команде владельца; не возвращать. Контакты оператора и параметры согласия — в site config. Не заявлять полное соответствие 152-ФЗ только на основании баннера и текстов.
- Никогда не выполняй команды с рекурсивным удалением вне рабочей папки проекта.
- Перед `git add` проверь перечень добавляемых файлов и отсутствие секретов; никогда не делай слепой `git add .` без просмотра результата.
- Не выполняй `push`/публикацию без явного запроса владельца. Отправка в `main` автоматически публикует результат.

## Контроль перед завершением задачи
1. `npm ci` (на чистой установке или в CI).
2. `npm run check` без ошибок.
3. `npm run build` без ошибок.
4. `npm run smoke` — проверяет реальные файлы сборки, base-путь, canonical и наличие страниц.
5. Локально открыть главную, блог, проекты, страницу статьи/кейса (если они есть) и 404; проверить мобильный экран, обе темы, навигацию, картинки и консоль браузера.
6. Передавать владельцу только реальные результаты: что сделано, какие проверки прошли, что осталось вручную в GitHub.
7. После проверки останавливать запущенные агентом локальные серверы и закрывать тестовые вкладки localhost.

## Обложки и контакты — уточнение владельца
- Для каждой статьи и кейса обязательна самостоятельная обложка в общем стиле: `docs/agents/prompts/BLOG_COVER_STYLE.md` и `docs/guides/BLOG_COVERS.md`. Сгенерировать через imagegen, не копировать сюжет и композицию предыдущих картинок. Поле `cover` обязательно.
- Любой email в интерфейсе и статьях — только текстовый адрес из `links` со ссылкой `mailto:`, без «Написать на почту», оформления кнопкой, пилюли, рамки, фоновой заливки и тени даже при hover.

- Все внешние HTTP/HTTPS-ссылки, включая Telegram и источники статей, открывать в новой вкладке с `target="_blank"` и `rel="noopener noreferrer"`. Внутренние ссылки и mailto не переводить в новые вкладки.

## Текущие страницы и прежние адреса — решение владельца от 23.10.2026
- Юридические документы находятся только в `src/pages/legal/`. Не возвращать страницы-копии `src/pages/privacy.astro`, `cookies.astro`, `consent.astro`.
- Все прежние адреса, включая документы, перечислены в `movedPaths` (`src/utils/routes.ts`); Astro регистрирует их через один `RedirectLayout.astro`. Они работают в разработке и сборке, закрыты от индексации и исключены из sitemap.
- Таблица SEO поддерживает стандартный Markdown-escape `\|` для визуальных редакторов и прежний `&#124;`. Оба варианта выводят буквальный символ |.
